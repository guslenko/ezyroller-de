# EzyRoller: тема и порядок обновлений

Магазин основан на официальном **PlentyONE Shop v2.45.0**. Точный коммит записан в `upstream-release.json`. Поле `version: 1.15.0` в package.json оставлено самим Plenty и не является номером релиза исходников.

## Что принадлежит магазину

- `runtime/pages/` — главная, business, kontakt, widerrufsformular, история, FAQ, подбор модели, уход, оформление юридических страниц и дополнительные переопределения страниц.
- `runtime/components/Home/` — баннеры, видео, таблицы сравнения, блоки истории/бизнеса/FAQ.
- `runtime/components/` — шапка, меню, выбор языка, подвал, оформление карточек, фильтров и блоков каталога.
- `runtime/layouts/default.vue` — компоновка с фирменной шапкой и статическим подвалом EzyRoller.
- `runtime/layouts/simplifiedHeaderAndFooter.vue` — checkout с белой шапкой и тем же фирменным подвалом, что на остальных страницах.
- `runtime/components/CheckoutPaymentButtons.vue` и `CheckoutGuaranteeLink.vue` — штатная кнопка оформления заказа с единственной PDF-ссылкой непосредственно под ней; стандартный `GuaranteeNotice` Plenty заменён в модуле пустым компонентом, чтобы не появлялся дубликат.
- `runtime/lang/{de,en,fr,it,es,pl}.json` — все исходные значения переводов магазина, сохранённые из e57f355. Редактировать тексты здесь.
- `runtime/server/api/` — серверные обработчики трёх собственных форм. Адреса `/api/business`, `/api/kontakt`, `/api/widerruf` сохранены.
- `runtime/plugins/` — GTM, Clarity, согласие на маркетинговые cookies и ecommerce-события магазина.
- `runtime/public/` — изображения и видео магазина, доступные по прежним `/images/...` и `/videos/...`.
- `branding.ts` и `runtime/assets/` — фирменные настройки и дополнительные стили.
- `migration-manifest.json` — соответствие исходных файлов и файлов модуля; `component-names.json` — имена компонентов для переопределения.

Оригинальные файлы Plenty находятся в `apps/web/app/`. Они служат основой обновлений; изменения магазина следует делать в модуле. Для новых компонентов добавить регистрацию в `index.ts` либо запись в manifest и component-names. Для новой страницы — запись в manifest. Поддерживающие типы/API Plenty проверять при каждом обновлении.

В `apps/web/nuxt.config.ts` остаются точки подключения: импорт `withEzyrollerTranslations`, вызов этой функции в `i18n`, регистрация `./modules/ezyroller` перед i18n и исключение повторной автоматической загрузки entrypoint. Не удалять их при разрешении конфликтов.

## Переводы

`i18n.ts` добавляет файлы магазина **после** штатных языковых файлов в конфигурации приложения. Поэтому совпадающий ключ получает значение EzyRoller, а новый отсутствующий ключ приходит из Plenty. Подключение только через `i18n:registerModule` не подходит для переопределения стандартных текстов: приоритет слоя приложения выше.

Сохранены все исходные значения шести языков, в том числе переводы стандартных ключей. Это намеренно: автоматическое принятие изменившегося стандартного текста поверх существующего текста магазина запрещено этой схемой. Новые ключи Plenty по-прежнему доступны.

## Аналитика и конверсии

Магазин использует контейнер `GTM-T24Q79K3`. При необходимости его можно заменить переменной `NUXT_PUBLIC_EZYROLLER_GTM_ID`. GTM, ADCELL и Microsoft Clarity (`wd1rqk9hv4`) загружаются только после соответствующего согласия на маркетинговые cookies и зарегистрированы в собственной теме, поэтому обновление Plenty их не удалит.

`runtime/plugins/tracking.client.ts` передаёт в `dataLayer` стандартные ecommerce-события `view_item`, `add_to_cart`, `remove_from_cart`, `begin_checkout` и `purchase`. Покупка содержит `transaction_id`, `value`, `currency`, `tax`, `shipping`, `coupon` и массив `items`; повторная отправка того же заказа в одной браузерной сессии блокируется.

Теги настраиваются в самом GTM на событие `purchase`:

- GA4 Event использует существующий Measurement ID `G-RKMMKJNST6`.
- Google Ads Conversion Tracking требует Conversion ID вида `AW-...` и Conversion Label; стоимость берётся из `ecommerce.value`, валюта из `ecommerce.currency`, идентификатор заказа из `ecommerce.transaction_id`.
- ADCELL настроен напрямую с Tracking ID `5625` и Event ID `7201`. Общий `trad.js` сохраняет affiliate-атрибуцию, а при создании заказа `/t/track.js` получает номер заказа, чистую стоимость товаров без НДС и доставки и код купона. При наличии ADCELL attribution-cookie middleware передаёт Plenty Referrer ID `18`.

Официальный модуль `@plentymarkets/shop-module-gtag` оставлен выключенным. GA4 уже загружается через GTM, поэтому включение модуля с тем же Measurement ID создаст дубли событий.

## Локальный запуск и проверка

```sh
nvm use 24
npm install
npm run dev
```

Открыть http://localhost:3000. API middleware работает на 8181. Для форм используются секреты и адреса из `apps/web/.env` (`NUXT_SMTP_*`, `NUXT_EMAIL_*`); файл остаётся локальным и исключён из Git. При переносе на сервер эти переменные нужно настроить отдельно. Пароль, ранее находившийся в исходниках, следует отдельно сменить у почтового провайдера.

```sh
npm run build
# При запущенном локальном магазине:
npm run test:ezyroller
```

Проверки обращаются только к GET страницам: фирменная главная на шести языках, таблица сравнения, подвал и собственные страницы/формы. Письма и заказы не отправляются. Другой локальный адрес можно задать через `EZYROLLER_TEST_URL`.

## Следующее обновление Plenty

1. Проверить текущую версию и сохранить проверенные изменения коммитом. Сделать отдельную ветку обновления.
2. Выполнить `npm run update:plenty -- vX.Y.Z` с точным номером официального релиза. Скрипт требует чистый Git, получает релиз только из официального репозитория и применяет разницу относительно сохранённого релиза через трёхстороннее слияние. Он не заменяет весь каталог свежими файлами, не публикует магазин и не затрагивает `.env` или модуль темы.
3. Если есть конфликты, скрипт останавливается. Сохранить подключения EzyRoller, согласовать новые зависимости с nodemailer и проверить интерфейсы переопределённых компонентов. После ручного завершения записать новый tag/commit в `upstream-release.json`. При конфликте lock-файла согласовать package.json и пересоздать lock-файл через npm.
4. Выполнить `npm install`, `npm run build`, `npm run dev`, `npm run test:ezyroller`. Проверить браузером каталог, товар, корзину, checkout, языки и формы с рабочим тестовым Plenty API.
5. Развёртывать только после проверки. Изоляция предотвращает перезапись собственной темы, но изменения API Plenty всё равно могут потребовать адаптации переопределений.

## Результат переноса 2026-09-14

- Исходное состояние: e57f355, ближайшая основа v2.24.0; в файлах были и более поздние изменения Plenty.
- Установлены исходники v2.45.0, Shop Core 1.36.0, Shop API 0.183.0, Nuxt 4.5.2, Node 24.
- Исходные словари de/en/fr/it/es/pl сравнивались целиком с e57f355: значения сохранены без изменений.
- Локальный middleware фильтрует посторонние cookies домена `localhost` перед запросами к Plenty. Без фильтра CloudFront отклонял большой заголовок с cookies других локальных проектов и каталог ошибочно показывал 404.
- Отправка форм, платежи и публикация не выполнялись.

Финальная проверка: `npm run build` прошла (включая проверку типов); 24/24 проверки `npm run test:ezyroller` прошли на собранной версии. Проверены страницы, приоритет переводов шести языков и прежние URL ресурсов. ESLint для index.ts, branding.ts и i18n.ts прошёл; весь исторический код темы не приводился к новым стилевым правилам Plenty. В браузере проверены главная, формы контакта/возврата, страница бизнеса, валидация пустой контактной формы и переключение языка.
